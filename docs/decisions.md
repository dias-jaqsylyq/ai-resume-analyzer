# Decisions

| Date | Decision | Why | Alternative considered |
| --- | --- | --- | --- |
| 2026-10-28 | Region us-east-1 | Nova Lite/Micro available in-region; Textract available | ap-southeast-1 (closer to HK, but Nova via cross-region only) |
| 2026-10-28 | Amazon Nova models only | Covered by AWS credits; budget ≈ $0 | Claude on Bedrock (billed via Marketplace, not covered by credits) |
| 2026-10-28 | Deploy via GitHub Actions + OIDC | No long-lived AWS keys anywhere; works from phone | AWS keys in cloud session env vars |
| 2026-10-28 | Bootstrap stack with local state | It creates the remote-state bucket itself; applied once by the owner | Click-ops in the console |
| 2026-10-28 | GitHub OIDC role trusted only for this repo's `main` and pull requests | No long-lived keys; other repos/branches cannot assume it | Wildcard `repo:owner/*` trust |
| 2026-10-28 | Deploy role temporarily has AdministratorAccess | Speed for a single-owner private repo; narrowing tracked as backlog task RA-24 | Hand-written least-privilege policy up front |
| 2026-10-28 | S3 native state locking (`use_lockfile`) instead of DynamoDB lock table | Fewer resources, supported since Terraform 1.10 | DynamoDB lock table |
| 2026-10-28 | OIDC trust matches GitHub's immutable subject (`repo:owner@ID/repo@ID:...`) with `StringEquals` | The repo uses `use_immutable_subject`; name-only `sub` was rejected (AccessDenied in CloudTrail). IDs also block repo-rename / name-reuse attacks | Name-only `sub` with wildcards |
| 2026-10-28 | One `ci` workflow; `aws-oidc-check` merged into the plan/apply jobs (they run `sts get-caller-identity`) | One place for PR checks; OIDC is still verified on every PR and every push to main | Keep a separate OIDC check workflow |
| 2026-10-28 | Main stack backend uses partial config: bucket passed with `-backend-config` from `vars.TF_STATE_BUCKET` | Bucket name contains the account ID; keeps it out of the repo and in one place | Hard-code the bucket name in `versions.tf` |
| 2026-10-28 | Apply on main re-plans and applies that saved plan; no GitHub environment on the apply job | The OIDC trust allows only `ref:refs/heads/main` and `pull_request` subjects; an environment would change the `sub` claim and be denied | Manual approval via a protected environment (needs a trust-policy change) |
| 2026-10-28 | Ruff config in root `ruff.toml`; tool versions pinned in `backend/requirements-dev.txt` | Same rules for all Python in the repo; local and CI results match | Config inside `backend/pyproject.toml` |
| 2026-10-28 | Shared JSON logger written on the standard library (`backend/src/resume_analyzer/log.py`), not AWS Lambda Powertools | Zero runtime dependencies and nothing to package per Lambda; we need only JSON lines, a correlation ID and Lambda context fields. Redacts CV/PII keys as a safety net | Powertools Logger (extra dependency/layer for a small feature set) |
| 2026-10-28 | Textract async API (`StartDocumentTextDetection` + `GetDocumentTextDetection`) polled from the `process-analysis` Lambda, with backoff and a stop 10 s before the Lambda deadline | Sync `DetectDocumentText` takes only single-page PDFs; a CV job finishes in seconds, so no SNS topic or second Lambda is needed | SNS completion notification + a separate Lambda |
| 2026-10-28 | Textract `ClientRequestToken` = SHA-256 of bucket/key/ETag | An SQS retry reuses the same Textract job instead of starting (and paying for) a new one | No token (every retry re-runs OCR) |
| 2026-10-28 | Upload key layout `uploads/<user_sub>/<analysis_id>.pdf`; uploads over 5 MiB rejected before Textract | The S3 event alone gives the user partition and the correlation ID; the size check avoids OCR cost on junk | Look the analysis up in DynamoDB by key |
| 2026-10-28 | AWS calls in tests are mocked with botocore `Stubber` on a pinned `boto3` (dev-only; the Lambda runtime ships boto3) | Stubber validates every request against the real API model, so invented parameters fail the tests; no extra mocking library | moto |
| 2026-10-28 | Every handler has a test that runs it on a synthetic CV at DEBUG and fails if any of the text reaches logs or stdout | Key-based redaction cannot catch text inside a free-text message | Rely on redaction and code review |
| 2026-10-28 | One customer managed KMS key (`alias/ai-resume-analyzer`) for S3, SQS and DynamoDB; S3 Bucket Keys on; SQS data-key reuse 24h | Each CMK costs $1/month; Bucket Keys and data-key reuse cut KMS requests (owner's rule) | One key per service; AWS managed keys (SQS→S3 event delivery to an encrypted queue needs a CMK whose policy allows S3) |
| 2026-10-28 | Annual automatic KMS key rotation enabled | Security best practice; no extra cost in year one (each rotation adds $1/month, capped at 2 rotations) | Rotation off |
| 2026-10-28 | Uploads expire after 7 days (`upload_retention_days`), incomplete multipart uploads after 1 day; no versioning; `force_destroy` on | CVs are personal data needed only for one run; keeps the stack destroyable for the "deploy from zero" metric | Versioned bucket with longer retention |
| 2026-10-28 | S3 → SQS notification only for the `uploads/` prefix; queue visibility = 6× Lambda timeout; DLQ after 3 receives, 14-day retention | AWS guidance for SQS-triggered Lambdas; enough retries for transient Textract/Bedrock errors; time to inspect failures | EventBridge between S3 and SQS (extra hop, no benefit here) |
| 2026-10-28 | DynamoDB on-demand, no point-in-time recovery | Zero cost at idle; data is re-creatable by re-running an analysis | PITR (billed per GB-month) |
| 2026-10-28 | Lambda roles created before the functions, each with only S3/SQS/DynamoDB/KMS(ViaService)/logs it needs; Textract and Bedrock permissions added in RA-7/RA-8 | Least privilege grows with each task; no unused permissions | One shared Lambda role |
| 2026-11-02 | Bedrock call behind a switch `BEDROCK_MODE=mock\|live` (default `mock`); mock = deterministic keyword match with the same report schema | The account still gets AccessDenied/throttling from Bedrock; the whole pipeline can be deployed and tested end to end without it, and nothing is billed until the switch is flipped | Block RA-8 on account verification |
| 2026-11-02 | Structured output via Converse tool use: one `submit_report` tool whose input schema is the report schema, forced with `toolChoice`; then our own validation, one retry on invalid output | Tool input comes back as parsed JSON, no free-text parsing; the schema is still validated because models can ignore constraints. A JSON object in a text block is accepted as a fallback | Ask for JSON in the prompt and parse text |
| 2026-11-02 | Default model `amazon.nova-lite-v1:0` (override `BEDROCK_MODEL_ID`), temperature 0, max 2000 output tokens, CV cut at 30k chars, JD at 10k | Cheapest Nova that handles a CV + JD comparison; bounded cost per call; Micro can be tried with the env var | Nova Pro (higher cost) |
| 2026-11-02 | Cache key = SHA-256(file bytes from S3, JD, model id, prompt version), looked up before Textract; 24 h TTL | Same CV + same JD skips both Textract and Bedrock. With SSE-KMS the S3 ETag is not a content hash, so the file is hashed (≤ 5 MiB) | Key on extracted text (still pays for Textract) |
| 2026-11-02 | Permanent errors (bad upload, missing analysis item, invalid model output after the retry, guardrail block) mark the item FAILED and are not retried; transient errors go back to SQS and the item is marked FAILED on the last receive (`MAX_RECEIVE_COUNT`, must equal the redrive `maxReceiveCount`) before the DLQ | A retry cannot fix a permanent error and would pay for Bedrock again; the user still sees FAILED instead of a stuck PROCESSING | Retry everything until the DLQ |
| 2026-11-02 | The analyses item stores only an error code (exception class name), never an exception message | Messages can carry content; the code is enough to show the user and to debug with logs | Store the message |
| 2026-11-02 | Lambda package = `backend/src` zipped by Terraform `archive_file` (hashicorp/archive), no build step | The backend's only runtime dependency is boto3, which the Python runtime ships; plan and apply build the same zip | Separate packaging job in CI uploading to S3 |
| 2026-11-02 | process-analysis: Python 3.13 on arm64, 256 MB, 120 s timeout; SQS mapping batch size 1, `ReportBatchItemFailures`, `maximum_concurrency = 2` | arm64 is cheaper per GB-second; concurrency cap protects Textract/Bedrock quotas and cost without reserved concurrency (new accounts may not have spare concurrency to reserve) | Reserved concurrency |
| 2026-11-02 | `BEDROCK_MODE` is a Terraform variable (`bedrock_mode`, default `mock`); IAM allows `bedrock:InvokeModel` only on the configured Nova model | Live calls are switched on by changing one variable after the owner's live check passes; nothing else changes | Separate live/mock functions |
| 2026-11-02 | Lambda log groups created by Terraform with 14-day retention, not KMS-encrypted | Logs hold only ids/counts (no CV text, enforced by tests); avoids extending the CMK policy to CloudWatch Logs | KMS-encrypted log groups |
